Discovery-to-brief in 15 minutes

5 steps: Get the customer's consent before recording, then record with a notetaker your company has approved (e.g. Fathom, Granola). If there is no recording, use your typed notes.

FDE Radar · 2026-10-16
Show details
1. Get the customer's consent before recording, then record with a notetaker your company has approved (e.g. Fathom, Granola). If there is no recording, use your typed notes.
2. Paste the transcript into your AI tool with the 'deal summary' prompt.
3. Ask it to list every assumption not stated by the customer.
4. Fix gaps with the user, then generate a 5-bullet brief for the AE and a follow-up email draft (use the second prompt). Do not send the email.
5. The user logs the brief in CRM and sets next-step dates.

Workflow

Account research before first call

5 steps: Ask the user to paste the company's public info (site pages, latest 10-K or press releases) and the attendees' titles. If you have web access, you may read public pages yourself; cite the URL for every fact. Do not scrape LinkedIn.

FDE Radar · 2026-10-16
Show details
1. Ask the user to paste the company's public info (site pages, latest 10-K or press releases) and the attendees' titles. If you have web access, you may read public pages yourself; cite the URL for every fact. Do not scrape LinkedIn.
2. Summarize business model, recent changes and likely priorities. Label every inferred pain or priority HYPOTHESIS.
3. Generate 10 discovery questions ranked by importance.
4. Flag 3 'not a fit' signals to watch for.
5. Return a one-page call plan with these sections: business model, recent changes, likely pains (hypotheses), 10 ranked questions, 3 not-a-fit signals, open questions.

Workflow

Agent POC with evals

5 steps: Pick one narrow task and collect 20–50 real example inputs (with permission).

FDE Radar · 2026-10-16
Show details
1. Pick one narrow task and collect 20–50 real example inputs (with permission).
2. Build the first version with an agent framework (e.g. LangGraph, OpenAI Agents SDK).
3. Write expected outputs and pass/fail checks for each input (first prompt), then run them through an eval tool (e.g. promptfoo, now part of OpenAI and still MIT open source, or DeepEval).
4. Trace failures with an observability tool (e.g. Langfuse, now part of ClickHouse and still open source, or LangSmith).
5. Report pass rate against the agreed criteria with the second prompt, not vibes. A zero-tolerance check that fails means the POC fails, whatever the average.

Workflow

Security questionnaire first pass

5 steps: Gather your approved security docs (SOC 2 summary, DPA, architecture).

FDE Radar · 2026-10-16
Show details
1. Gather your approved security docs (SOC 2 summary, DPA, architecture).
2. Prompt the AI to answer only from those docs and mark gaps NEEDS REVIEW.
3. Route NEEDS REVIEW items to security/legal owners.
4. Store final, approved answers in your RFP tool (e.g. Loopio, or Responsive, formerly RFPIO) for reuse.
5. Track turnaround time per questionnaire.
